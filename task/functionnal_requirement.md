# Функциональные требования

Краткое резюме. Полное описание — в [system-design.md](system-design.md).

Приложение-обёртка над Keitaro. Список и редактор видят только компании из своей базы.

## Сущности

- **Company** — имя из формы, как в Keitaro, уникально регистронезависимо; после создания не меняется; `lifecycle` (`creating` / `ready`), `version`, traffic status.
- **Stream** — принадлежит Company. Свои два: `google` (гео, редирект, в редакторе без разбора фильтра) и `offers`. Чужие потоки без офферов — `plain`, только строка.
- **Offer** — карточка Keitaro по id. Каталог только для чтения, в базу не пишется.
- **stream_offer / stream_offer_snapshot** — обе копии: `percent`, `pinned`, `position`, `removed`. Архив остаётся после Push.

## Создание

Форма: имя, список гео-кодов, один оффер (100%). Домен, группа, источник из env. Ротация потоков по позиции. Идемпотентность через `Idempotency-Key`.

## Правки

- Офферы: действие + `expected_version` → рабочая копия → Push.
- Remove серит строку и ставит в UI 0%. Bring back желтит поток. Push архив не стирает.
- Гео: отдельно, Keitaro first, только фильтр потока `google`.
- Cancel возвращает снимок. Fetch при белом потоке пишет снимок, гео и traffic и оставляет поток белым. При жёлтом или непустой очереди отклоняется.
- localStorage — очередь непринятых действий, не копия состояния.

## Веса

После действия редактора сумма участников = 100. Fetch может принести иную сумму, утилита догонит её на следующем действии. `pin` замораживает текущий процент. Bring back снимает pin у возвращённого оффера. Хвост раздаётся по `position`, затем `offer_id`.

## Enable / disable

Со списка компаний. Keitaro first. Доли не меняются.

## Вне ТЗ (принято)

docker-compose, pytest (веса + sync с моком), JWT-аутентификация.
