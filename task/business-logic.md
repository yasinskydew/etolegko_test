# Бизнес-логика

Краткое резюме. Полное описание — в [system-design.md](system-design.md).

Пользователь говорит только с бэкендом. С Keitaro говорит только бэкенд.

| | Бэкенд | Keitaro |
|---|---|---|
| Компания | Обёртка, имя из формы, lifecycle, version, признак трафика | Кампания с тем же именем |
| Потоки | `google`, `offers`, при необходимости `plain` | Фильтр стран на первом потоке и состав офферов на втором. Ротация по позиции |
| Оффер | Участник или архив `removed` | В трекере только участники и их доли |
| Вес | Утилита на бэкенде; в трекер уходят участники | Доли этих офферов |
| Гео | Список кодов из `geo` | Фильтр потока `google`. В редакторе фильтр не показывается |
| Домен, группа, источник | Имена из env, id при старте | Хранит на кампании |

`pinned`, `removed` и статус синхронизации в Keitaro не уходят.

## Сценарии (кратко)

- **Создание.** Один оффер (100%), список гео, `Idempotency-Key`. Сначала резерв в Postgres (`creating`), затем кампания и два потока в Keitaro, снимок → `ready`.
- **Правка офферов.** Действие + `expected_version` → утилита → рабочая копия (жёлтый поток) → Push → снимок вместе с архивом (белый поток).
- **Remove / Bring back.** Серая строка с 0% в UI остаётся после Push. Bring back снимает pin у этой строки и снова желтит поток.
- **Гео / enable / disable.** Keitaro first, затем база. Cancel их не откатывает.
- **Cancel.** Очередь localStorage очищается, рабочая копия = снимок, Keitaro не трогаем.
- **Fetch.** При белом потоке и пустой очереди: пропавшие офферы становятся архивом, снимок, гео и traffic обновляются, поток остаётся белым. Доли не нормализуются. При жёлтом потоке запрос отклонён.
- **Клик после Push.** Keitaro: страна из списка компании → Google, остальные → офферы второго потока по `percent`.
